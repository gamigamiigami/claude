# 席替えツール 設計図

## 1. プロジェクト概要

### 1.1 目的
学校の先生が**最小限の操作で席替えについて考えて決定できる**ツールを提供する。

### 1.2 動作環境
| 項目 | 内容 |
|------|------|
| 対応端末 | iPad（Safari）/ Windows PC（Chrome / Edge） |
| 形式 | **単一HTMLファイル**（`index.html`） |
| サーバー | 不要（ブラウザで開くだけで動作） |
| ネットワーク | 不要（完全オフライン動作） |
| データ保存 | ブラウザのlocalStorage＋JSONファイルのバックアップ機能 |
| 対象 | 学校・教室の席替え |

### 1.3 設計方針
- **インストール不要**：HTMLファイルをブラウザで開くだけ
- **タッチ操作対応**：iPadでもタップで全操作が可能
- **データの永続化**：ブラウザを閉じても設定・履歴が残る
- **印刷対応**：座席表・班名簿をそのまま印刷できる

## 3. 画面構成（7タブ構成）

```
┌──────────────────────────────────────────────┐
│ 📋 席替えツール   [教室選択▼] [＋新規] [💾保存] [📂読込] │
├──────────────────────────────────────────────┤
│ 🏫教室設定 │ 👥生徒 │ 🎨グループ │ 🚫NG設定 │ 🎲席替え │ 📃名簿 │ 🕐履歴 │
└──────────────────────────────────────────────┘
```

### 3.1 🏫 教室設定タブ
- 列数（横）×行数（縦）の入力 → 「レイアウト適用」
- 座席マップ（黒板が前）をクリックして机を選択
  - **向き変更**：前向き↑ / 横向き（左）← / 横向き（右）→
  - **席の無効化**：通路・空席として机を取り除く

### 3.2 👥 生徒タブ
- 生徒の追加（名前入力＋Enter）
- CSVインポート（1行1名で貼り付け）/ CSVエクスポート
- 生徒ごとの操作：
  - **編集**：名前変更・グループ変更・**固定席の設定**
  - **除外**：席替え対象から一時的に外す（転校・欠席など）
  - **削除**

### 3.3 🎨 グループタブ
- 班の追加（自動で色が割り当て）
- 色の変更（色ドットをタップで切り替え）
- 班名の変更（直接編集）
- メンバーの追加・削除（チップをタップ）
- **均等自動振り分け**ボタン

### 3.4 🚫 NG設定タブ
- **隣席NG**：生徒A × 生徒B（＋理由メモ）→ 隣同士にならない
- **着席NG**：生徒を選択 → グリッドの席をタップしてNG席を登録/解除

### 3.5 🎲 席替えタブ（メイン画面）
- **「🎲 席替え実行」ボタン** → 制約を満たすランダム配置を生成
- 座席表表示：
  - 班の色で背景色分け
  - 🔒 = 固定席
  - ⚠️ / ℹ️ = 警告ありの席（枠色も変化）
- **警告パネル**（タップで該当席をハイライト）：
  - ❌ エラー：NG条件を満たせなかった場合
  - ⚠️ 警告：前回と同じ席
  - ℹ️ 情報：過去に隣だった / 同じ班だったペア
- 「💾 履歴に保存」「🖨 印刷」ボタン

### 3.6 📃 名簿タブ
- **班別名簿**（班の色付きカード、座席位置付き）を自動生成
- 座席表の印刷ビュー
- 印刷時はボタン・タブを自動的に非表示（`@media print`）

### 3.7 🕐 履歴タブ
- 保存した配置の一覧（ラベル＋日付）
- **表示**：過去の座席表をプレビュー
- **この配置を使う**：席替え画面に復元
- **削除**

## 5. 席替えアルゴリズム

### 5.1 制約の分類

**ハード制約（絶対に守る）**
- 固定席：指定生徒は必ずその席
- 着席NG：指定生徒はその席に座れない
- 隣席NG：NGペアは上下左右に隣接しない

**ソフト制約（警告として表示・配置自体は許可）**
- 前回と同じ席ではないこと
- 過去に隣だった相手と再び隣にならないこと
- 過去に同じ班だった相手と再び同じ班にならないこと

### 5.2 アルゴリズムの流れ

```
1. 有効な席のリストを作成（無効化された机を除く）
2. 生徒を「固定席あり」「固定席なし」に分ける
3. 生徒数 > 席数 ならエラーで中断
4. 固定席の生徒を先に配置
5. リスタートループ（最大300回）:
   a. 残りの生徒と席をシャッフル（Fisher-Yates）
   b. 各生徒について順番に:
      - 着席NGでない席
      - すでに配置済みの隣にNGペア相手がいない席
      を探して配置
   c. 全員配置できたら成功 → ループ終了
   d. 配置できない生徒がいたら次のリスタートへ
6. 300回失敗した場合:
   - NG隣接制約を緩和して強制配置
   - 「条件を完全に満たせなかった」エラーを警告に追加
7. ソフト制約チェックを実行して警告リストを生成
```

### 5.3 ソフト制約チェック（履歴照合）

```
同じ席チェック:
  最新の履歴エントリと比較し、同じ席キーに同じ生徒IDがあれば警告

隣履歴チェック:
  全履歴について、各生徒の当時の隣接者集合を計算
  → 今回の隣接者と重複があれば「○○と××は『第N回』でも隣でした」

同班履歴チェック:
  全履歴の groupSnapshot を参照
  → 今回も同じ班のペアが過去にも同じ班だった場合に警告
```

### 5.4 隣接の定義
上下左右の4方向（無効化された机は隣接に含めない）。

## 6. 主要関数一覧

| 関数 | 役割 |
|------|------|
| `loadState()` / `saveState()` | localStorageとの読み書き |
| `createClassroom(name, rows, cols)` | 教室の新規作成 |
| `getDeskMeta(cr, r, c)` | 机のメタ情報取得（なければデフォルト生成） |
| `getEnabledSeats(cr)` | 有効な席のキー一覧 |
| `getNeighbors(cr, key)` | 上下左右の隣接席キー |
| `runSeatingAlgorithm(cr)` | 席替え本体（制約付きランダム配置） |
| `hardConstraintOk(cr, student, seat, assignment)` | ハード制約の判定 |
| `checkSoftConstraints(cr, assignment)` | 履歴照合・警告生成 |
| `isNGPair(cr, idA, idB)` | NGペア判定 |
| `renderGrid(containerId, cr, mode, extra)` | 座席グリッド描画（全タブ共通） |
| `saveCurrentAsHistory()` | 現在の配置＋班構成を履歴に保存 |
| `restoreHistory(hid)` | 履歴の配置を復元 |
| `importStudentCSV(text)` / `exportStudentCSV()` | 名簿のCSV入出力 |
| `exportData()` / `importData(event)` | 全データのJSONバックアップ・復元 |

## 7. UI/UX設計

### 7.1 タッチ対応（iPad）
- タップターゲットは最小44pxを確保
- ドラッグ&ドロップを使わず「**選択 → タップ**」の2タップ方式
  - 例：NG席設定 = 生徒を選択 → 席をタップ
- ネイティブの `<select>` を使用（iOSのピッカーが開く）

### 7.2 色設計
- 班カラー：10色のプリセット（赤・橙・黄・緑・青緑・青・紫・桃・茶・灰）
- 座席の背景 = 班カラーの20%透過、枠 = 班カラー
- 警告レベル：❌赤（エラー）/ ⚠️黄（警告）/ ℹ️青（情報）

### 7.3 印刷
- `@media print` でタブ・ボタン類を非表示
- 名簿タブの内容（班別名簿＋座席表）のみが印刷される

## 8. データ管理・安全性

| 項目 | 対策 |
|------|------|
| データ消失防止 | 「💾保存」でJSONファイルとしてダウンロード可能 |
| 端末間の移行 | JSONファイルを「📂読込」で別端末に取り込み |
| 削除事故防止 | 生徒・グループ・履歴の削除前に確認ダイアログ |
| 複数クラス対応 | 教室を複数作成・切り替え可能 |

> **注意**: localStorageはブラウザごとに独立しているため、
> iPadとPCでデータを共有するにはJSONエクスポート/インポートを使う。
